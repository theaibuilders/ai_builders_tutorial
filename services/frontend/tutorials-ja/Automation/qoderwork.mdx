# QoderWork：カスタムSkillsの構築と使用

QoderWorkは、Mac上でファイル整理、データ分析、ドキュメント作成などのマルチステップタスクを自律的に実行するデスクトップAIエージェントです。**Skills**は拡張レイヤーで、コミュニティマーケットプレイスのものも、自分で構築したものも、再利用可能な自動化モジュールとしてQoderWorkを強化できます。

このチュートリアルでは、Skillsマーケットプレイスのナビゲート、Skillsのインストールと管理、適切なファイル構造でゼロからカスタムSkillを作成する方法まで、すべてをカバーします。

## 前提条件

- ローカルマシンにQoderWorkデスクトップアプリがインストールされている
- アクティブなQoderアカウント（無料枠で可能）
- JSON/YAMLとMarkdownの基礎的な知識

## プロジェクト構造

始める前に、このチュートリアルで構築するカスタムSkillのファイルレイアウトを示します。

```
my-skill/
├── SKILL.md          # 必須 — スキルメタデータ（YAML frontmatter + 説明）
├── prompt.md         # 変数を含むタスクテンプレート
├── config.json       # オプション — デフォルトパラメータと設定
└── README.md         # オプション — 人間向けドキュメント
```

カスタムSkillをインストールする際、このフォルダをzipにしてQoderWorkにドラッグします。zipのルートに`SKILL.md`があることだけが**必須**です。



## ステップ1：Skillsマーケットプレイスを探索

1. QoderWorkを開き、左サイドバーの**Skills**をクリックします。
2. **Skills Marketplace**タブが表示されます — Official SelectionとOther Skillsを閲覧します。
3. **Filter**ドロップダウンを使ってカテゴリで絞り込みます（例：**Content Creation**、**Data & AI**、**Design & UI**、**DevOps & Deployment**、**Docs & Writing**、**Productivity**、**Research & Analysis**）。

注目すべき組み込みマーケットプレイスSkillsには、`deep-research`、`cloudflare-deploy`、`notion-infographic`、`file-organizer`、`frontend-design`があります。

4. **Built-in**タブに切り替えて、QoderWorkに同梱されているSkillsを確認：`agent-browser`、`docx`、`pdf`、`pptx`、`xlsx`、`find-skills`、`install-skill-dependency`。
5. **User-installed**に切り替えて、追加したSkillsを管理 — マーケットプレイスからのものもローカルインストールしたものも。



## ステップ2：マーケットプレイスSkillをインストール

マーケットプレイスからのインストールはワンクリックです：

1. **Skills Marketplace**タブで、任意のスキルカード（例：`deep-research`）をクリックします。
2. **Install**をクリックします。
3. スキルが**User-installed**タブに表示され、有効/無効を切り替えられます。
4. 更新が利用可能な場合、**Update**バッジが表示されます — クリックして最新版を取得。

**カスタムまたはサードパーティのSkill**を`.zip`ファイルとしてインストールするには：

1. **+ Install skill**をクリック（右上隅）。
2. ダイアログで`.zip`ファイルをドラッグ＆ドロップ、またはクリックして参照。
3. zipのルートに`SKILL.md`が含まれている必要があります — 以下のファイル要件を参照。
4. **Install**をクリック。



## ステップ3：最初のカスタムSkillを作成

`weekly-report` Skillを構築します。これはプロジェクトフォルダをスキャンし、その週の変更点のMarkdownサマリーを生成します。

### 3a. フォルダ構造を作成

```bash
mkdir -p ~/skills/weekly-report
cd ~/skills/weekly-report
```

### 3b. `SKILL.md`を作成

これが唯一の必須ファイルです。YAML frontmatterがメタデータを定義し、本文がQoderWorkがSkillを起動するタイミングを判断するためのトリガー説明です。

```markdown

name: weekly-report
version: 1.0.0
description: >
  Scans a specified project folder for files modified in the past 7 days
  and generates a weekly-report-{date}.md summary with changes, action
  items, and a file diff overview. Trigger when the user asks for a
  weekly summary, weekly report, or week-in-review for a folder.
category: Productivity
author: your-name


## Weekly Report Skill

Generates a structured weekly report from any local project folder.
Useful for standups, client updates, and personal progress tracking.

### When to trigger
- User says "create a weekly report for [folder]"
- User says "summarize this week's changes in [folder]"
- User asks for a "week in review" of a directory

### Variables
- `{{folder}}` — absolute or relative path to the project folder
- `{{date}}` — auto-filled with today's date (YYYY-MM-DD)
- `{{format}}` — output format, default is `markdown`
```

### 3c. `prompt.md`を作成

これはSkillがトリガーされた際にAIに送信されるタスクテンプレートです。

```markdown
# Task: Weekly Report for {{folder}}

Scan the folder at `{{folder}}` and perform the following steps:

1. **List modified files** — find all files modified in the last 7 days.
   Include file name, path, size, and last-modified timestamp.

2. **Categorize changes** — group files by type:
   - New files (created this week)
   - Modified files (changed but not new)
   - Deleted files (if detectable via git or trash)

3. **Extract action items** — scan `.md`, `.txt`, and `.docx` files for
   lines containing TODO, ACTION, FIXME, or [ ] checkbox syntax.

4. **Generate report** — write the output to:
   `{{folder}}/weekly-report-{{date}}.md`

   Use this structure:
   ```
   # Weekly Report — {{date}}

   ## Summary
   - X files modified, Y files created, Z action items found

   ## Modified Files
   | File | Type | Last Modified |
   ||||
   | ...  | ...  | ...           |

   ## Action Items
   - [ ] Item from file.md
   - [ ] Another item

   ## Notes
   _Auto-generated by QoderWork weekly-report Skill_
   ```

5. **Confirm completion** — respond with the path to the generated report.
```

### 3d. `config.json`を作成

Skill変数に事前入力するオプションのデフォルト値：

```json
{
  "defaults": {
    "format": "markdown",
    "lookback_days": 7,
    "include_hidden": false,
    "action_item_keywords": ["TODO", "ACTION", "FIXME", "[ ]"]
  },
  "permissions": {
    "file_access": "read-write",
    "scope": "specified_folder_only"
  }
}
```

### 3e. `README.md`を作成

```markdown
# weekly-report Skill

Generates a Markdown weekly report from any local project folder.

## Usage

In QoderWork chat, type:

```
Create a weekly report for ~/Projects/my-app
```

Or invoke directly with:

```
@weekly-report folder=~/Projects/my-app
```

## Output

Creates `weekly-report-YYYY-MM-DD.md` in the target folder.

## Permissions Required

Read-write access to the target folder.
```



## ステップ4：Skillをパッケージしてインストール

```bash
cd ~/skills
zip -r weekly-report.zip weekly-report/
```

zipの構造は次のようになります：

```
weekly-report.zip
└── weekly-report/
    ├── SKILL.md        ← 必須、フォルダのルートに配置する必要がある
    ├── prompt.md
    ├── config.json
    └── README.md
```

インストール：

1. QoderWork → **Skills** → **+ Install skill**をクリック
2. `weekly-report.zip`をダイアログにドラッグ
3. **Install**をクリック
4. **User-installed → Local install**に表示されます



## ステップ5：Skillを使用

Skillをインストールしたら、2つの方法でトリガーできます。

**自然言語：**
```
Create a weekly report for ~/Projects/my-saas-app
```

**`@`による直接呼び出し：**
```
@weekly-report folder=~/Projects/my-saas-app
```

QoderWorkは実行前に実行プランを表示します。確認して**Execute**をクリックします。



## ステップ6：組み込みの`create-skill`ヘルパーを使用

QoderWorkにはインタラクティブにガイドする組み込みの`create-skill` Skillがあります。チャットで次のように入力：

```
Help me create a skill using create-skill. Please detect the current
environment first and save the skill to the correct path: in a VM
environment, save to /root/.qoderwork/skills/; otherwise save to
~/.qoderwork/skills/. First, ask me what the skill should do.
```

QoderWorkがSkillの目的についてインタビューし、`SKILL.md`を自動生成して正しいローカルパスに保存します。

**Skillsの保存先：**

| 環境 | パス |
|-||
| ローカルMac | `~/.qoderwork/skills/` |
| VM / Docker | `/root/.qoderwork/skills/` |



## ステップ7：SkillsでのMCP統合

Skillsは外部統合のためにMCP（Model Context Protocol）サーバーを呼び出すことができます。`prompt.md`でMCPツールを次のように参照します：

```markdown
# Task: Deploy to Cloudflare

Use the `cloudflare-deploy` MCP tool to:
1. Build the project at `{{project_path}}`
2. Deploy to Cloudflare Workers
3. Return the live URL
```

Skillsで使用する前に、**Settings → Integrations → MCP**でMCPサーバーを設定してください。



## トラブルシューティング

**インストール後にSkillが表示されない** — zipのルートに`SKILL.md`があることを確認（余分なフォルダの中にネストされていないか）。

**間違ったプロンプトでSkillがトリガーされる** — `SKILL.md`の`description`フィールドのトリガーフレーズをより具体的にする。

**実行時に権限エラー** — **Settings → File Access**に移動し、対象フォルダを読み書き権限で追加。

**依存関係の不足** — 組み込みの`install-skill-dependency` Skillが、不足しているランタイム依存関係を自動的に診断・修正できます。
