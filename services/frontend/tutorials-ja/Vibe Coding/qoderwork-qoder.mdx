# 3時間で作る「Best of Tokyo」シティガイド

<Callout type="info">
これは **AI Builders x Qoder** によるハンズオンワークショップです。AI ツールを使って調査し、作り、発表します。コーディング経験は不要です。
</Callout>

## このワークショップで作るもの

このワークショップの最後には、次の 3 つが完成します。

1. **リサーチ成果物** — 東京の特定エリアやテーマに沿った実在スポット、レビュー、ローカル情報の curated collection（QoderWork を使用）
2. **インタラクティブなシティガイド** — カード、フィルター、マップ表示を備えた美しい Web アプリ（Qoder を使用）
3. **プレゼン資料** — あなたのガイドと制作プロセスを紹介するビジュアルなスライドデッキ（QoderWork を使用）

参加者それぞれが自分のテーマを選ぶので、完成するガイドはすべて違うものになります。

- モダンな Web ブラウザ（Chrome 推奨）
- コーディング経験は不要

## フェーズ 1: QoderWork でリサーチ

**時間: 25 分**

QoderWork はあなたの AI リサーチアシスタントです。自然な会話だけで、Web 検索、複数ソースの要約、構造化ドキュメントの作成まで行えます。

### Step 1.1 — テーマを決める

まずは自分が本当に面白いと思えるテーマを選びましょう。このガイドは *あなた自身の* ガイドです。個性を出して構いません。

**エリア別の例:**
- 下北沢のベストスポット（古着、カフェ、ライブハウス）
- 谷中のベストスポット（下町、寺、ローカルスナック）
- 中目黒のベストスポット（川沿い散歩、デザインショップ、ブランチ）
- 高円寺のベストスポット（古着、アンダーグラウンド音楽、安くておいしい店）

**テーマ別の例:**
- 東京のベストラーメン
- 隠れ喫茶店ガイド
- 深夜の東京（バー、居酒屋、ナイトライフ）
- デザイン好きのための東京（建築、ギャラリー、ショップ）
- 予算 1000 円以下で楽しむ東京

<Callout type="example">
**本当に自分が行ってみたいテーマを選ぶのがコツです。** テーマが具体的なほど、ガイドは魅力的になります。たとえば「東京の食」より「新宿のラーメン」のほうが面白くなります。
</Callout>

### Step 1.2 — スポットを調べる

**QoderWork** を開いて、次のように話しかけます。

```text
[あなたのテーマ] についてのシティガイドを作っています。

実在する場所を 6〜8 件リサーチして、各スポットについて次の情報を集めてください。
1. 名前（日本語 + 英語）
2. 一言説明（その場所の魅力）
3. 住所
4. おおよその価格帯（¥ / ¥¥ / ¥¥¥）
5. おすすめの時間帯
6. 観光客があまり知らないローカルな豆知識

数より質を重視してください。有名な定番スポットと、
あまり知られていないローカルなお気に入りをバランスよく入れてください。
```

QoderWork は Web を検索し、複数ソースを突き合わせながら、実在スポットの正確な情報を整理してくれます。

### Step 1.3 — 文脈とストーリーを加える

良いガイドは、ただの一覧ではありません。そこに物語や空気感があります。続けて QoderWork にこう頼みます。

```text
次に、このガイドに編集的な文脈を加えてください。

1. このガイドの雰囲気が伝わる短い導入文を 3〜4 文で書いてください。
   なぜこのテーマやエリアが面白いのか、どんな空気感なのかを入れてください。
2. 4〜5 スポットを自然につなぐ散策ルートを提案してください。
3. 初めてこのテーマを楽しむ人向けの「プロ向けヒント」を 3 つください。
4. フィルターに使えるタグやカテゴリを提案してください
   （例: "budget-friendly", "rainy day", "date spot", "solo-friendly"）。
```

### Step 1.4 — データを構造化する

次のフェーズで使いやすいように、QoderWork にデータを整理してもらいます。

```text
ここまでの内容を、Web アプリで使える JSON 構造のドキュメントとしてまとめてください。
各スポットは次の形式にしてください。

{
  "name_en": "",
  "name_ja": "",
  "description": "",
  "address": "",
  "price": "",
  "best_time": "",
  "insider_tip": "",
  "tags": [],
  "lat": null,
  "lng": null
}

さらに、導入文、散策ルート、プロ向けヒントも
別フィールドとして含めてください。最後にファイルとして保存してください。
```

<Callout type="success">
**チェックポイント:** 6〜8 件の実在スポット、導入文、散策ルート、プロ向けヒント、タグを含む構造化データができているはずです。これが Web アプリの中身になります。
</Callout>

## フェーズ 2: Qoder でシティガイドを Vibe Coding する

**時間: 60 分**

ここからは **Qoder** を使って、リサーチ内容を実際に動くインタラクティブな Web アプリに変えていきます。Qoder は agentic AI coding platform です。自然言語で要件を伝えると、構成を考え、コードを書き、改善まで進めてくれます。

### Step 2.1 — ベースアプリを作る

**Qoder** を開いて新しい workspace を作り、リサーチデータを貼り付けたうえで次のプロンプトを渡します。

```text
以下のリサーチデータを使って、React のシティガイド Web アプリを作ってください。

[ここに JSON データを貼り付ける]

アプリには次の要素を含めてください。
1. ヒーローセクション
   - ガイドタイトル
   - 導入文
   - 雰囲気のある背景画像（プレースホルダーまたはグラデーションで可）
2. フィルターバー
   - タグでスポットを絞り込めるようにする
3. カードグリッド
   - 各スポットをカード表示し、以下を含める
   - 名前（日本語 + 英語）
   - 説明
   - 価格帯
   - おすすめ時間帯
   - タグを小さなバッジとして表示
4. 詳細表示
   - カードをクリックすると insider tip を展開する
5. 下部に "Pro Tips" セクションを追加

Tailwind CSS を使ってください。表計算のようではなく、
雑誌の特集ページのような、エディトリアルでモダンな雰囲気にしてください。
シングルページアプリで、バックエンドは不要です。
```

Qoder がどのように進めるかを観察してみてください。コンポーネント構成を考え、コードを書き、プロジェクトを立ち上げてくれます。

### Step 2.2 — 見た目を磨く

ベースができたら、次のプロンプトでデザインを整えます。

```text
デザインを次のように改善してください。
- ダークテーマを採用し、暖色系のアクセントカラー（amber / orange 系）を使う
- カードに控えめなホバーアニメーションを追加する
  （少し浮く + シャドウ）
- ヒーローセクションにグラデーションオーバーレイを追加する
- 日本語に合うクリーンなフォントスタックにする
  （英語は system-ui、日本語は Noto Sans JP をフォールバック）
- カード表示時に滑らかなフェードインアニメーションを追加する
- タグのフィルターピルをデザイン誌の UI のように見せる
```

### Step 2.3 — インタラクションを加える

ガイドをもっと生きた体験にします。

```text
次のインタラクティブ機能を追加してください。
1. タグフィルターをクリックしたとき、カードグリッドをアニメーションさせる
   （表示対象はフェードイン、非表示対象は滑らかにフェードアウト）
2. "Walking Route" セクションを追加し、
   おすすめルートを番号付きステップと接続線で表示する
3. 各カードに "copy address" ボタンを追加し、
   日本語の住所をクリップボードにコピーできるようにする
4. 小さなマッププレースホルダーを追加し、
   静的な埋め込み地図画像またはイラストを表示する
```

### Step 2.4 — レスポンシブ対応

スマホでも見やすくしておきます。参加者は友達に見せたくなるはずです。

```text
アプリを完全にレスポンシブにしてください。
- モバイルではカードを 1 カラムで縦積みにする
- 小さい画面ではフィルターバーを横スクロール可能にする
- ヒーローセクションの文字がどの画面サイズでも読みやすいようにする
- すべての操作要素をタップしやすいサイズにする
```

### Step 2.5 — 最終仕上げ

```text
最後の仕上げをしてください。
- フッターに "Made with AI Builders x Qoder" と今日の日付を入れる
- ページ読み込み時に控えめなアニメーションを追加する
- 全体の余白とリズムが整って見えるようにする
- 価格帯の横に絵文字を追加する（💰 💰💰 💰💰💰）
```

<Callout type="tip">
**Vibe Coding のコツ:** コードを理解しようとしすぎなくて大丈夫です。見るべきなのはブラウザ上の見た目です。もし何か違和感があれば、「カードが少し詰まりすぎている」「色が明るすぎる」といった自然な言葉で伝えれば、Qoder が修正してくれます。
</Callout>

<Callout type="success">
**チェックポイント:** 動くインタラクティブなシティガイドがブラウザで確認できる状態になっているはずです。テーマやデザインの選び方によって、参加者ごとにまったく違う作品になります。プレゼン用にスクリーンショットを撮っておきましょう。
</Callout>

## フェーズ 3: QoderWork でプレゼン資料を作る

**時間: 20 分**

次は成果を発表できる形にまとめます。**QoderWork** を使って、見栄えの良いスライドデッキを作成します。

### Step 3.1 — スライドデッキを作る

**QoderWork** に戻って、次のように依頼します。

```text
私の東京シティガイドプロジェクトを紹介する、5 枚のビジュアルなスライドデッキを作ってください。

Guide title: [タイトル。例: "Hidden Kissaten: Tokyo's Retro Coffee Shops"]
Theme: [テーマ]
Number of spots: [スポット数]
Key highlights: [特に気に入っているスポットを 2〜3 件]

Slide structure:
Slide 1: Title slide — ガイド名 + "Built with Vibe Coding"
Slide 2: The Concept — このガイドが何についてのものか、誰向けか
Slide 3: Highlights — 印象的な 2〜3 スポットを説明付きで紹介
Slide 4: The Build Process — QoderWork で調査 → Qoder でコーディング → 合計 3 時間
Slide 5: Try It Yourself — QR コード用プレースホルダー + AI Builders / Qoder のリンク

見た目はクリーンでモダンにしてください。.pptx として保存してください。
```

### Step 3.2 — スクリーンショットを入れる

```text
Slide 3 または 4 に、アプリのスクリーンショットを置くスペースを追加してください。
プロっぽく見えるように、デバイスのモックアップフレームを付けてください。
```

### Step 3.3 — デモ用の話す内容を作る

```text
このプロジェクトをデモするための 60 秒の発表スクリプトを書いてください。
次の流れを含めてください。
1. 何を作ったか、なぜこのテーマを選んだか（10 秒）
2. ガイド機能の簡単な紹介（30 秒）
3. どう作ったか — QoderWork で調査、Qoder でコーディング（15 秒）
4. 締めの一言（5 秒）

営業っぽくならず、自然で会話的なトーンにしてください。
```

## デモタイム

発表時間は **2 分** です。次の流れで紹介しましょう。

1. ガイドのテーマと、それを選んだ理由を短く紹介する
2. ブラウザでライブアプリを見せる — スクロールし、いくつかカードを開き、フィルターも使ってみる
3. リサーチで見つけたお気に入りのスポットを 1 つ紹介する
4. どう作ったかを説明する（調査 → コード → 発表、すべて AI で）

### 重要なポイント

- **QoderWork** は、リサーチ、文章作成、ドキュメント生成を会話だけで進められます。Web 検索から構造化出力まで対応できます。
- **Qoder** は、あなたの指示を実際に動くコードへ変えてくれます。あなたが方向を決め、Qoder が形にします。
- **Vibe Coding** では、何を入れるか、どう見せるかといった創造的な意思決定に集中できます。実装は AI が大部分を担います。
- 手でコードを書かなくても、3 時間でひとつの完成プロジェクトを出せます。
