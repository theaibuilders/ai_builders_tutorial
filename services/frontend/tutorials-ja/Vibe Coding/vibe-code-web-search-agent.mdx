# バイブコードでWeb検索AIエージェントを構築・デプロイ

## 概要
このチュートリアルでは、完全な**Web検索AIエージェント**を構築します。これはPython FastAPIバックエンドとReactフロントエンドを備えたフルスタックアプリケーションで、ウェブを検索して質問に知的な回答を提供できます。エージェントはLLMを使用してWeb検索が必要かどうかを判断し、検索クエリを抽出し、BrightDataのSERP APIを通じてリアルタイム結果を取得し、RAG（検索拡張生成）パターンを使用して包括的な回答を合成します。

アプリケーションにはユーザー制御の「Web検索」チェックボックスが含まれており、以下を切り替えることができます：
- **有効**: エージェントはBrightDataを使用してWebを検索し情報を合成
- **無効**: エージェントはLLMモデルの知識のみに依存しWeb検索を行わない
![with-or-without-web-search](/workshops/with-or-without-web-search.png)

### プロンプト5: ウェブ検索

> **目的:** BrightDataを使用したウェブ検索機能を作成

```
BrightDataのSERP APIを使用してウェブ検索を行いたいです。

services/backend/scraper.py に以下の機能を持つPythonクライアントを作成してください：
- 検索クエリを受け取りGoogle検索結果を返す
- https://api.brightdata.com/request のBrightData APIを使用
- 解析された検索結果をJSONとして返す
- エラー処理をクラッシュなしで行う

APIはBearerトークン認証を使用し、以下のパラメータが必要です：
- zone: "serp_api1"
- format: "json"
- data_format: "parsed_light"

重要な修正点：
1. urllib.parse.quote_plus をインポートして使用し、Google検索URL構築前に検索クエリをURLエンコードしてください
2. "language"パラメータを含めないでください (BrightDataはそれを拒否します)
3. BrightDataは {status_code, headers, body} 構造のレスポンスを返します。_parse_search_resultsで：
   - データに 'body' フィールドがあるか確認し抽出
   - bodyがJSON文字列の場合、json.loads()で解析
   - 次に 'organic' または 'organic_results' フィールドを検索結果として探す
```

**期待される出力:**
ウェブ検索と結果返しが可能なクラスを含む `scraper.py` ファイル

### プロンプト6: AIエージェント

> **目的:** 検索タイミングを決定するインテリジェントエージェントを構築

```
今度はすべてを統合するAIエージェントを構築します。

services/backend/agent.py に以下の機能を持つエージェントを作成してください：
1. ユーザーの質問を受け取る
2. LLMを使用して判断: "これは現在のウェブ情報が必要ですか？"
3. はいの場合: 検索キーワードを抽出し、ウェブ検索を行い、結果に基づいて回答
4. いいえの場合: LLMの知識から直接回答

エージェントは作成したLLMクライアントとウェブスクラッパーを使用してください。各ステップで何が起こっているか確認できるようにロギングを追加してください。

重要: answer()メソッドはuse_web_searchパラメータを受け入れる必要があります (デフォルトはTrue)。
use_web_searchがFalseの場合、ウェブ検索決定ロジックを完全にスキップしてLLMの知識から直接回答してください。
```

**期待される出力:**
LLM推論とウェブ検索をオーケストレーションするインテリジェントエージェントを含む `agent.py` ファイル

### プロンプト7: APIサーバー

> **目的:** エージェントをREST APIとして公開

```
services/backend/main.py に以下の機能を持つFastAPIサーバーを作成してください：
- 質問を受け取りエージェントの回答を返すPOST /api/queryエンドポイント
- ヘルスチェックエンドポイント (GET / と GET /health)
- config.py設定を使用して環境変数からAPIキーを読み込み
- フロントエンドから呼び出せるようにCORSを有効化

リクエストは {"query": "...", "use_web_search": true} で、レスポンスは {"answer": "..."} である必要があります。

重要: 非推奨の@app.on_event("startup")および@app.on_event("shutdown")デコレーターを使用しないでください。
代わりに現代的な方法を使用してください：
1. contextlibからasynccontextmanagerをインポート
2. スタートアップとシャットダウンを処理するlifespan非同期コンテキストマネージャー関数を作成
3. FastAPIに渡す: app = FastAPI(lifespan=lifespan)

これにより非推奨警告を回避します。
```

**期待される出力:**
エージェントを公開するFastAPIサーバーを含む `main.py` ファイル

## 技術的ノート (インストラクター用)

これらのプロンプトは、エラーのない実装を保証するために特定の技術的詳細で強化されています：

1. **プロンプト3** - コンマ区切り文字列を解析するためのpydantic field_validatorを使用したCORSバリデータ
2. **プロンプト5** - quote_plusによるURLエンコード、サポートされていない言語パラメータ削除、BrightDataレスポンスボディ抽出とJSON解析
3. **プロンプト6** - 条件付き検索ロジックのためのuse_web_searchパラメータ
